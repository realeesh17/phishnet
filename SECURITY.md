# Security Policy

## Reporting a Vulnerability

PhishNet is a security-focused project, and reports of potential vulnerabilities are welcome.

Please do not publish sensitive vulnerability details in a public issue or pull request.

If GitHub private vulnerability reporting is enabled for this repository, use the **Report a vulnerability** option in the repository's Security tab. Otherwise, contact the maintainer through their GitHub profile and request a private channel for sharing the details.

## What to Include

When reporting a potential vulnerability, include:

- A clear description of the affected feature or component.
- The steps needed to reproduce the issue.
- The potential security impact and realistic attack scenario.
- Relevant logs, screenshots, or proof-of-concept details, with secrets and personal data removed.
- Any suggested mitigation, if known.

## Responsible Disclosure

- Give the maintainer a reasonable opportunity to investigate and address the issue before public disclosure.
- Do not access, modify, or disrupt data or systems that do not belong to you.
- Test only against systems you own or have explicit permission to assess.
- Do not include real credentials, API keys, personal information, or live victim URLs in reports.

## Scope

This policy applies to the PhishNet source code and project components maintained in this repository. Third-party services and external websites are outside the project's control.
